# CABTO 下一步评估与执行计划（2026-09-28）

> 本文档记录「接下来该怎么做」的评估结论，以及据此确定的三步执行方案。原始评估回答见正文，随后的三步执行见对应实验产物与报告。

---

## 一、当前进度：工程基础足够，方法有效性还没有证明

| 已有工作 | 已经证明 | 尚未证明 |
|---|---|---|
| P0 分层干预 | 给定正确修订，有限场景下可以完成任务 | 系统能自主提出修订 |
| P1 真实 9B 提案 | 能提出局部有效参数，能拒绝错误候选 | 完整修复、交互节省 |
| 224 条多图数据 | 采集、配对、时间隔离和导出可用 | 数据具有足够的机制多样性 |
| 12 步 LoRA | 真实更新、保存和重载可用 | 结构化生成正确、诊断有效、修复有效 |

三个决定后续路线的问题：

1. **P1 首先失败在候选生成，而不是排序。** 三次生成池都没有完整可确认的修订；模型把 `stack` 的放置失败也解释成抓取高度问题。因此先优化排序未必能解决问题——池里没有解，排序再好也找不到。但 P1 还有一个限制：它测试的是「一次提案，然后搜索固定池」，没有充分测试 CABTO 应有的「执行后再提案、保留局部进展」。

2. **当前训练数据离核心难题还有距离。** 224 条来自 32 个配对组，但只有 4 个 scene-seed 上下文，主要是一个程序家族、固定高度偏移和一个简单效果遗漏。`diagnosis` 标签主要由已有结果布尔值生成，`update` 主要比较干预前后结果，输入已含成功/契约检查等强提示。复述它们不等于学会归因。真正值得学习的是：下一项干预会怎样、应该先试什么、何时应停止。

3. **自由生成还没验收通过。** 上一轮「生成冒烟通过」只表示接口能运行；实际回复被截断、JSON 无效、且出现复述输入内容的现象。目前还不能把适配器直接接到修订执行器上。

## 二、调整研究主线：从「解释失败」转向「选择并验证修复」

| 内容 | 谁负责 |
|---|---|
| 实际状态变化、违约谓词、失败 API 阶段 | 确定性程序计算 |
| 可能需要改哪一层、下一项区分性试验 | 模型提出 |
| 候选是否格式合法、安全、可执行 | 固定校验器 |
| 干预是否有效、能否迁移、是否破坏旧任务 | 真实执行与独立验证 |

不要花大量训练成本让 VLM 学习程序已经能精确计算的状态差异。模型输出应缩短为：对应哪个动作、哪段证据；修订候选或下一项试验；预期改善什么、仍可能留下什么问题；继续试验/局部进展/待确认/弃权。

## 三、推荐实施顺序

- **阶段 A：先验收「能不能产生可用决策」**（不新增物理采集，先用现有数据）——比较未微调模型、当前 12 步适配器、确定性规则基线，覆盖 diagnosis/forecast/update 及只修模型/只修策略/联合修订；检查 JSON 与字段合法率、证据忠实性、是否复述整段输入而无决策、能否区分物理成功与契约一致、能否保留局部进展。
- **阶段 B：优先做 P2 增量修订实验**（不微调）——从「一次生成完整候选」改为「按动作整理证据 → 提出局部修订 → 执行 → 判断新增进展与剩余缺陷 → 保留有效补丁 → 再提出修订 → 独立确认」。核心是「保留有效部分，再补剩余缺陷」。
- **阶段 C：根据 P2 失败类型，决定训练什么**——训练优先级调整为：候选结果预测／下一项试验选择 ＞ 干预后更新 ＞ 长文本失败解释。

## 四、进入 240 组 Pilot 前如何补数据

重点增加四种变化：参数不固定为 0 与 45mm；同一机制对应不同程序实现（真实生成程序＋自然失败）；包含多个有效修复与错误修复；加入后继任务（抓取成功后必须检验放置/释放/稳定保持）。派生问答、干预分支和近似程序必须整组绑定；已用于改提示/选模型的数据不能再冒充未见测试。

---

## 五、如何真正回答「更少交互找到正确修订」

拆成两个问题：

- **问题 1：模型能否提出正确修订？** 固定总输出 token、重提次数和物理预算，统计候选结构合法率、有执行支持的局部改善、最终通过独立确认的修复率。
- **问题 2：模型能否更快找到它？** 同候选池下比较固定顺序、随机顺序、模型排序/按反馈调整顺序；各方法真实执行，不把缓存重排当在线节省；池里没解要单独报告。

主指标：**给定交互预算内，找到经独立确认、完成完整任务且不破坏回归任务的修复比例。** 同时报告首次确认修复所需交互、错误接受、无谓修订、弃权、旧任务退化、API/仿真/重置/前缀重放成本。确认执行也计入预算。

---

## 六、VLM 是否值得保留，要作为实验问题

必须比较规则/数值状态基线、同基座 text-only 微调、图像＋状态微调。若 text-only 一样好甚至更好，并不否定 CABTO，只说明当前贡献在跨层修订与试验选择，而不是视觉表示。

---

## 七、最终结论与三步执行

下一轮集中交付三件事：

1. **可用决策输出验收**：从「能生成文本」推进到「能产生合法、忠实的决策」。
2. **P2 增量修订闭环**：优先验证按阶段反馈、保留部分修复是否改善原 P1 失败。
3. **同预算修复曲线**：与规则和固定搜索比较，明确收益来自候选生成、反馈更新还是试验选择。

暂不做：扩大模型、长轮次训练、PPO、更多相同截图、继续优化视觉缓存。

最值得争取的下一条结论不是「训练 loss 继续下降」，而是：

> **在全新的任务上下文中，CABTO 能用真实执行证据逐步修对，并在相同成功标准下减少交互。**
